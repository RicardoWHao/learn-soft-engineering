# 06 工程进阶、SEO、性能与故障排查

> 本页把前五个模块串到工程落地：Markdown 高阶能力、被搜索引擎收录、性能与多版本，以及一套「本地好的线上挂」的系统排查方法。目标是遇到问题能按链路定位，而不是靠猜。
**前置依赖**：子模块 03（主题）、子模块 04（构建）、子模块 05（部署）
**适用版本**：VitePress `1.6.4`；i18n/代码导入/sitemap 能力在 1.x 稳定。
---
## 一、Markdown 高阶能力
这些能力本质都在子模块 04 的 markdown-it 编译期落地：
- **自定义容器**：`::: info / tip / warning / danger` 生成带语义色的提示块，也可用 `::: 标题` 自定义标题。
- **代码组**：用 `::: code-group` 包裹多个带文件名注释的代码块，渲染为带 Tab 的切换。
- **代码高亮控制**：代码块语言标注、`{1,3-5}` 行高亮、`// [!code focus]` / `// [!code --]` / `// [!code ++]` 等行内指令，都在构建期由 Shiki 处理。
- **导入代码片段**：用 `<<< @/path/file.ts#snippet` 从源文件按 region 导入真实代码，避免示例与源码脱节。
- **Markdown 中用 Vue**：直接写模板语法、导入组件；需要仅客户端渲染的内容用 `<ClientOnly>` 包裹。
- **全局组件**：在主题 `enhanceApp` 注册后，任意 md 可直接用。
```markdown
::: warning 构建期生效
容器与高亮都是构建期生成的静态 HTML，不是运行时组件。
:::
```
## 二、SEO 与可发现性
静态预渲染已保证正文可被抓取，进一步要补的是元信息与地图：
- `head`/`transformHead`：为每页设置 title、description、canonical、Open Graph 卡片字段；可用 `useData()` 读取页面信息动态生成。
- `sitemap.hostname`：开启后构建产出 `sitemap.xml`，向搜索引擎提交；配合 `robots`（可由静态文件或平台规则提供）控制收录。
- 语义化结构：用规范的 H1/H2/H3（右侧大纲依赖它），URL 用语义化短路径，避免上线后再改路径（改了要做 `rewrites`/301）。
- 社交分享卡片、favicon 通过 `head` 的 link/meta 配置。
## 三、性能优化（先分清构建期还是运行时）
| 层面 | 成本来源 | 治理手段 |
| --- | --- | --- |
| 构建期 | 逐路由 SSR、Shiki 高亮、搜索索引 | 开启 `cache`、CI 缓存依赖与 cache 目录、按需高亮语言、`search.exclude` 缩小索引 |
| 首屏运行时 | JS 体积、水合、首屏图片 | Vite 自动按路由分包；控制自定义组件体积；图片压缩与懒加载 |
| 搜索 | 索引 JSON 体积 | 排除目录、调 MiniSearch 字段权重/分词；过万页换 Algolia |
| 分发 | 重复回源 | hash 资源长缓存 + HTML 短缓存 + CDN |
一个认知要点：默认主题的运行时已经很轻，多数「卡」其实是构建期耗时或超大图片/索引，不要在运行时方向上盲目优化。
## 四、多语言（i18n）与多版本
- i18n：在配置中用 `locales` 定义多语言根路径（如 `/`、`/en/`），各自配 nav/sidebar 与文案；目录按语言分文件夹，构建产出多套路由。
- 多版本文档（如 v1/v2）：静态站没有内建版本切换数据库，常见做法是不同目录或不同构建分支分别发布，再在主题里加版本切换链接；大型项目也可用社区插件。规划阶段就要定好 URL 结构，后期迁移成本高。
## 五、团队协作与发布纪律
- 内容改动走功能分支 + PR：只合入 main 才触发发布，PR 阶段可借助平台的预览部署（Vercel/Netlify 原生支持）提前看效果。
- 仓库里只提交源码、配置、lock 文件与主题；`node_modules`、`dist`、`cache` 一律 gitignore。
- 文件名统一小写连字符，新增页面成对完成「建 md + 登记 nav/sidebar」，让构建期 dead link 检查守最后一道关。
## 六、故障排查方法论：按链路分段
按「文件 → 路由 → 构建 → 部署 → CDN/浏览器」逐段确认，能快速定位：
| 症状 | 优先怀疑的环节 | 关键动作 |
| --- | --- | --- |
| 点击链接 404 | 路由/文件 | 查文件是否存在、是否有分区 `index.md`、路径大小写 |
| 构建报 dead link | 链接登记 | 补齐目标 md 或修正 link；不要用忽略检查掩盖 |
| 页面裸奔无样式 | base/部署路径 | Network 看资源路径与前缀，修正 `base` |
| 本地好、线上旧 | CDN/浏览器缓存或部署未成功 | 查 Actions 运行结论；强刷；核对 hash 文件名 |
| 水合报错 | SSR/CSR 不一致 | `onMounted` 后读浏览器状态或套 `ClientOnly`，preview 复现 |
| 搜索搜不到新页 | 索引/收录范围 | 查 `exclude`、清 `.vitepress/cache` 重建 |
## 七、实战场景
### 场景 1：文档代码示例与真实源码逐渐不一致
治理：用代码片段导入（`<<< @/...#region`）让文档直接引用仓库里的源文件，构建期取最新内容，从机制上消除「示例漂移」；CI 里源码改动会随构建失败暴露无效引用。
### 场景 2：站点收录量低、分享到 IM 没有卡片
定位：先 curl 页面确认正文在 HTML（排除 SPA 空壳问题），再查 head 是否有 description 与 Open Graph、是否产出并提交了 sitemap、robots 是否误禁。修复：补 `transformHead` 元信息、开启 sitemap 并在站长平台提交。
### 场景 3：页面上千后 `vitepress build` 越来越慢
分段确认是 SSR 还是高亮/索引耗时：开启持久化 `cache`、CI 缓存 npm 与 `.vitepress/cache`、Shiki 语言按需、搜索 `exclude` 精简索引；单机内存不足导致 OOM 时给 Node 提高 `--max-old-space-size`，但首选仍是缩小单页体积与索引而非堆内存。
## 八、关键问题思考
1. **[高频] 概念题：`::: tip` 容器和代码组是运行时组件吗？** 不是，它们在构建期由 markdown-it 编译成静态 HTML/少量前端 Tab 逻辑；自定义容器是 Markdown 语法糖，不依赖你写组件。
2. **[高频] 原理题：如何保证文档里的代码示例不和源码脱节？** 用代码片段导入（`<<< @/路径#region`）在构建期从源文件抽取真实代码，源码改了构建即同步，引用失效还会在构建期暴露。
3. **[高频] 场景题：SSG 已经对 SEO 友好，还要做什么？** 补每页 title/description/canonical/Open Graph（`head`/`transformHead`），开启并提交 sitemap，用语义化标题层级和短路径，必要时配 robots；预渲染只解决「正文可抓」，元信息仍要补齐。
4. **[中频] 原理题：站点变慢应优先怀疑哪里？** 默认运行时很轻，先区分构建期还是运行时：多数是构建期逐路由渲染/高亮/索引，或超大图片。用 cache、CI 缓存、按需高亮、缩小搜索索引、压缩图片解决，而不是盲目改运行时。
5. **[高频] 机制题：hash 资源长缓存为什么不会让用户拿到旧版？** 文件名含内容 hash，内容变则文件名变；入口 HTML 短缓存并引用新文件名，发版后用户从新 HTML 拿到新 hash 资源，旧缓存只服务于未变更文件。
6. **[中频] 概念题：多语言怎么组织？** 用 `locales` 为每种语言定义根路径与独立 nav/sidebar/文案，目录按语言划分，构建产出多套路由；URL 结构要在规划期定好。
7. **[高频] 排查题：上线后某页 404 的标准定位顺序？** 先查文件是否存在与路径拼写/大小写（Linux 敏感），再查分区是否缺 `index.md`，然后看构建是否曾报 dead link、部署是否成功，最后区分是否为 CDN/浏览器缓存。按「文件→路由→构建→部署→缓存」逐段收敛。
8. **[高频] 排查题：hydration mismatch 怎么修？** 找出 SSR 与客户端首次渲染结果不同的值（时间、随机数、`window`/`localStorage`），把读取推迟到 `onMounted` 或用 `<ClientOnly>` 包裹；用 `build` + `preview` 在本地复现，因为 dev 不做完整 SSR。
9. **[中频] 工程题：哪些东西不该提交进仓库？** `node_modules`、`dist`、`cache` 都是可再生的依赖与产物，应 gitignore；只提交 Markdown 源、配置、自定义主题、`package.json` 与 lock 文件，由 CI 统一安装构建。
